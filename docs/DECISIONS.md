| D-22 | Hasil rekomendasi hanya untuk user dari session; Food nonaktif dan rekomendasi yang kini sudah dinilai disaring saat query. | Perubahan rating tidak menjalankan ulang CF di backend dan tidak membocorkan user lain. **Implemented; owner/filter PostgreSQL integration Tested**. |

| D-25 | Peringatan kandidat rekomendasi terbatas muncul bila ≥90% pengguna USER masing-masing telah menilai ≥90% makanan aktif. | Heuristik UI untuk menjelaskan kepadatan data, bukan aturan algoritme atau validasi publikasi. | D-29 | Rating changes use a PostgreSQL singleton revision trigger; snapshots lock/capture revision with rating rows. | Inserts, deletes, or actual score changes dirty dataset; same-value updates do not. | D-30 | Scheduling uses the existing Python worker poll loop and PostgreSQL state/config locks; automatic dedupe hashes rating revision, engine version, and frozen parameters. | No second queue, worker, Redis, Celery, Next.js timer, or service. | D-31 | Production gate stays closed in PostgreSQL/API: auto-processing/publication false and validation `PENDING_VALIDATION`; DB trigger rejects `AUTO_RATING_CHANGE`. | Separate E2E-only `_test` path uses `TEST_PROTOTYPE` without changing production config/constraints. | D-32 | Admin monitoring reuses existing protected API; display-only dashboard cannot change validation gate or automatic processing/publication. | Reports config/gate, revision dirty state, scheduler, job counts, last completion, worker heartbeat, recent-job safe detail, artifact staleness, and last published batch.
